# 公開行程：正式 UI 與 IndexedDB 整合

實作日期：2026-10-21（Asia/Taipei）。設計依據：[核准設計稿](../../../poc/ui/public-itinerary-sharing-workflow.html)。

使用真正專案的 `npm run dev`，登入後於側欄進入「公開行程」（`/public-itineraries`）。個人行程的「行程操作」提供發佈、更新公開版本及下架；既有新增、編輯、刪除、路線圖與協作功能保留。未儲存草稿時分享按鈕停用，確認後才寫入。

## 資料與操作

- TravelDatabase / SyncDatabase 升至版本 10，新增 `publicItineraries` store：`&id, &sourceTripId, createdAt, updatedAt`。既有資料原樣保留，不寫入範例，不搬移 PoC 資料。
- 核心實作位於 `core.ts`，POC 改為引用同一核心及正式型別。發佈與更新完整重建公開快照；套用完整重建個人區域、地點、標籤、行程與項目，保留日期及項目內容，交易完成後才通知成功。
- 套用區域名稱 `<公開區域名稱>(分享)`；新標籤 `<公開行程名稱>(分享)`，使用現有標籤色盤隨機選色。全部複製地點指向同一次套用的標籤。副本名稱依第一個未占用的 `（副本）`、`（副本 2）` 命名，每次套用獨立。
- 單機模式直接使用正式 `travel-planner` IndexedDB；帳號本機工作區使用既有 LocalSyncStore 的帳號檢查與交易追蹤。套用的個人資料走既有完整操作記錄，公開快照不加入個人同步資料。本次不新增雲端公開資料功能；純雲端資料模式不啟用分享操作。
- 本機變更依 Dexie 的交易完成通知刷新既有模組，區域／地點／標籤／行程可直接查看新增資料；其他資料庫或同步 metadata 的通知不觸發刷新。套用不自動跳到副本。

## UI 與刪除邊界

公開預覽重用現有 `ItineraryModule`，由 `SnapshotItineraryService` 提供快照內容與地圖資料；不讀來源或私人標籤，拒絕所有寫入操作。原有 Google 地圖、日期切換、項目時間／交通／路程顯示沿用。下架或跨分頁刪除公開記錄後預覽消失，不能再套用。

行程刪除沿用既有 TripRepository：刪除項目、路線圖與附加地點，保留區域、地點與標籤供既有模組管理。來源刪除不連帶刪除公開快照，更新拒絕；可從公開列表的「下架」入口清理失去來源的公開版本。

現有個人資料備份格式維持不變，套用後的副本與分享標籤包含在個人備份。公開快照目前不納入個人備份；覆蓋匯入個人資料不刪除公開快照，單機「清空所有資料」會一併清除公開快照。

## 手動驗收

1. 在現有專案建立或選取一個有區域、地點與每日項目的個人行程，從「行程操作」發佈；取消應不寫入，確認後公開列表出現。
2. 從側欄預覽公開行程，切換日期，確認沒有編輯或私人標籤／地點備註。
3. 套用後到真正的區域、地點、標籤模組，確認 `(分享)` 區域、分享標籤及全部地點，再從行程標題選單自行選取副本。可照常編輯副本。
4. 修改來源名稱與項目後，公開預覽保持原內容；確認更新後完整覆蓋，新增日期保留、副本不變。
5. 用既有刪除行程功能刪除來源，公開內容仍可套用；從公開列表下架。刪除套用副本不影響公開版本或其他副本。
6. 重新整理／重開確認資料保留；跨分頁下架後已開啟的預覽消失，套用已下架 ID 會拒絕。
