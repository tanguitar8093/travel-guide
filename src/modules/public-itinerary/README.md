# 公開行程：正式 UI 與 IndexedDB 整合

實作日期：2026-10-21（Asia/Taipei）。設計依據：[核准設計稿](../../../poc/ui/public-itinerary-sharing-workflow.html)。

使用真正專案的 `npm run dev`，登入後於側欄進入「公開行程」（`/public-itineraries`）。個人行程的「行程操作」提供發佈、更新公開版本及下架；既有新增、編輯、刪除、路線圖與協作功能保留。未儲存草稿時分享按鈕停用，確認後才寫入。

## 資料與操作

- TravelDatabase / SyncDatabase 升至版本 10，新增 `publicItineraries` store：`&id, &sourceTripId, createdAt, updatedAt`。既有資料原樣保留，不寫入範例，不搬移 PoC 資料。
- 核心實作位於 `core.ts`，POC 改為引用同一核心及正式型別。發佈與更新完整重建公開快照；套用完整重建個人地圖、地點、標籤、行程與項目，保留日期及項目內容，交易完成後才通知成功。
- 套用地圖名稱 `<公開地圖名稱>(分享)`；新標籤 `<公開行程名稱>(分享)`，使用現有標籤色盤隨機選色。全部複製地點指向同一次套用的標籤。副本名稱依第一個未占用的 `（副本）`、`（副本 2）` 命名，每次套用獨立。
- 單機模式直接使用正式 `travel-planner` IndexedDB；帳號本機工作區使用既有 LocalSyncStore 的帳號檢查與交易追蹤。套用的個人資料走既有完整操作記錄，公開快照儲存在跨帳號的共用公開目錄，不加入個人同步資料。公開快照使用下述獨立 Supabase 同步協定；純雲端模式也提供發佈、更新、下架與交易式套用。
- 本機變更依 Dexie 的交易完成通知刷新既有模組，地圖／地點／標籤／行程可直接查看新增資料；其他資料庫或同步 metadata 的通知不觸發刷新。套用不自動跳到副本。

## UI 與刪除邊界

公開預覽重用現有 `ItineraryModule`，由 `SnapshotItineraryService` 提供快照內容與地圖資料；不讀來源或私人標籤，拒絕所有寫入操作。原有 Google 地圖、日期切換、項目時間／交通／路程顯示沿用。下架或跨分頁刪除公開記錄後預覽消失，不能再套用。

行程刪除沿用既有 TripRepository：刪除項目、路線圖與附加地點，保留地圖、地點與標籤供既有模組管理。來源刪除不連帶刪除公開快照，更新拒絕；可從公開列表的「下架」入口清理失去來源的公開版本。

現有個人資料備份格式維持不變，套用後的副本與分享標籤包含在個人備份。公開目錄不納入個人備份；覆蓋匯入或清空個人資料不影響共用目錄，已發佈的內容請從公開列表明確下架。

## 手動驗收

1. 在現有專案建立或選取一個有地圖、地點與每日項目的個人行程，從「行程操作」發佈；取消應不寫入，確認後公開列表出現。
2. 從側欄預覽公開行程，切換日期，確認沒有編輯或私人標籤／地點備註。
3. 套用後到真正的地圖、地點、標籤模組，確認 `(分享)` 地圖、分享標籤及全部地點，再從行程標題選單自行選取副本。可照常編輯副本。
4. 修改來源名稱與項目後，公開預覽保持原內容；確認更新後完整覆蓋，新增日期保留、副本不變。
5. 用既有刪除行程功能刪除來源，公開內容仍可套用；從公開列表下架。刪除套用副本不影響公開版本或其他副本。
6. 重新整理／重開確認資料保留；跨分頁下架後已開啟的預覽消失，套用已下架 ID 會拒絕。

驗證結果：107 項正式整合及相關回歸測試、29 項 PoC 契約通過，strict 型別檢查與專案建置通過。新增模組針對性 lint 無錯誤；既有 ItineraryModule 的 React Compiler 警告仍存在。

## 跨帳號公開目錄修正

公開內容改存獨立 IndexedDB `travel-planner-public-catalog`，同一瀏覽器、同一 origin 的所有帳號讀取同一列表。每筆保存 `ownerId` 與 `sourceWorkspaceId`；只有發佈者可更新／下架，其他帳號只提供預覽與套用。套用的完整個人圖仍寫入目前帳號自己的工作區，不把來源私人資料暴露給其他帳號。

先前帳號隔離資料庫中的公開快照會一次性匯入目錄並保留身份／時間，marker 防止下架後復活。舊單機資料庫沒有發佈者資訊的公開快照不自動指定給目前登入者，匯入後提供唯讀／套用。新的單機發佈保存當前帳號身份。

此段記錄原本的 IndexedDB 階段；目前已加入下述 Supabase 雲端同步，公開內容可跨裝置讀取。

驗收：A 帳號發佈後切換 B，公開列表應仍有該行程；B 可預覽、套用，其既有地圖／地點／標籤／行程模組應出現自己的副本，但沒有 A 的下架入口。切回 A 可更新／下架，B 的副本不受影響。


## Supabase 與本地同步（2026-10-21）

已安裝 `supabase/migrations/20261021042447_public_itinerary_sync.sql` 至目前設定的 Supabase。只增加新物件；安裝前後個人資料表筆數及 `app_sync_push`、`sync_private.record` 定義一致。未建立／重播既有 migration history。停用檔位於 `supabase/rollback/20261021042447_public_itinerary_sync.sql`，僅撤銷新功能存取，保留資料。

| IndexedDB／核心 | Supabase | 用途 |
| --- | --- | --- |
| publicItineraries | public.public_itineraries | 獨立快照、發佈者、來源 UUID、雲端時間與版本 |
| syncTasks | public_itinerary_private.receipts | 本地操作佇列及雲端去重回執 |
| baselines | version / sequence / withdrawn | 樂觀版本檢查與下架傳播 |
| syncMetadata | app_public_itinerary pull cursor | 每次最多 100 筆，完整拉取所有頁 |

公開目錄 Dexie v2 按 Supabase project hostname 隔離；舊目錄與同專案工作區資料一次性匯入。來源 UUID 無個人行程外鍵，刪除來源不刪公開版本。所有公開快照可由 anon / authenticated 讀取；member / admin 才能發佈，更新與下架嚴格限定發佈者本人（admin 不繞過）。公開表沒有直接 DML 權限，私有 helper 驗證身份、來源、欄位白名單及關聯；公開 RPC 為 invoker wrapper。地點私人備註、標籤與額外欄位不能上傳。

發佈／更新／下架在同一 IndexedDB 交易保存內容與待同步操作。登入、操作完成、恢復連線、回到頁面，以及前景每 60 秒同步；公開頁也提供手動同步和進度。只有當前帳號的操作會上傳，切換帳號後不接受舊回應。Web Locks 避免分頁同時執行同步。操作 ID 與 payload 在送出前凍結；網路失敗保留供重試。相同操作回執不重複寫入；較新的雲端版本不會被較舊成功回執覆蓋。

雲端衝突時保留本機內容與操作，不自動重送覆蓋。「採用雲端版本」經使用者確認才丟棄此公開版本的待同步操作；個人來源與套用副本不變。需要再發佈自己的內容時，可從來源選單重新更新。離線下架先移除本機內容；其他裝置須在上傳及拉取完成後才看見下架結果。

混合模式套用沿用既有個人同步 outbox，副本會跟隨既有個人同步偏好上傳。純 IndexedDB 模式的個人副本仍維持本機資料模式；公開版本照常同步。純 Supabase 模式讀取一筆一致的來源快照，套用透過雲端單筆交易建立全部個人圖，並由既有 triggers 產生個人同步 events。雲端套用保留操作 ID，結果不確定時重試不多建副本。

自動驗證：公開分享／同步及相關個人回歸 70 項、PoC 契約 29 項；build 與針對性 lint 通過。協作測試已對齊目前「已啟用協作／請使用共享行程」提示；依使用者要求移除以狀態通知判定同步完成的前景輪詢測試，正式同步程式未修改。完整測試目前 57 檔、540 項全部通過；資料庫 schema 複製案例單獨通過，僅提高該案例逾時至 30 秒以容納完整並行測試負載。遠端 advisors 無 ERROR，新增物件無 advisory；16 項既有 performance WARN 保留。遠端匿名 pull 與 member 發佈／重試／套用／分享標籤／下架 smoke 通過，smoke 交易完整 rollback。

跨裝置驗收：A 發佈並確認待同步為零；B 在不同瀏覽器／裝置登入，同步公開列表後預覽及套用。A 更新、下架並同步後，B 再同步應取得新版／移除公開版本，B 已套用副本保留。離線修改後重整仍保留佇列；重新連線會同步。兩台裝置同時更新時後送出的舊版本應提示衝突。
