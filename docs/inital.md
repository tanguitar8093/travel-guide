我想建立一個行程規畫表系統

模糊需求:

- 能在排行程時, 方便記錄景點和規畫景點
- 在旅行時, 看著排好的行程, 能更好掌握地點時間等資訊
- 日後能持續擴充修改行程

流程:

- 記錄景點資料庫，可用 Google 地圖搜尋選擇地點或提供自訂地圖網址 (搭配標籤綁定, 日後好搜尋) >
- 建立旅行地圖範圍區域, 所有的景點都會標示在這範圍內 (EX.沖繩,台灣,台中市...) >
- 建立行程表:
  - 每個行程會拿紀錄好的景點(可用標籤 filter), 綁定 標註交通方式, 前往地點時間, 停留時間, 備註等資訊
  - 行程頁面左側顯示每日行程、右側顯示旅行範圍地圖與區域內所有可定位地點；當日已排地點依順序編號標示
  - Google 地點座標僅供地圖即時定位，不寫入景點資料；只有自訂網址的地點可能無法自動定位
- 建立的過程後結果都會直接和資料庫同步, 不用事後才存檔

概念:
所有實作都在前端完全, 暫時沒有後端和 API,
概念上的大架構,會有: 資料庫, 邏輯層, UI
實作順序匯市 資料庫 > 邏輯層 > UI
理念是分別設計模組, 模組會支援開放封閉原則的擴充性, 以及最小改動類別的維護性,
個別小功能開發完最終才會整合

框架:
預計會使用 typscript + react, 要先幫我安裝好初始環境

第二步預計設計 label 模組, 但如果有其他建議也可以改變順序
