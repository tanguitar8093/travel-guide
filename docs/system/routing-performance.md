# 台灣路由與搜尋效能量測

現行跨縣市策略已由 [C7 系統性修正](osm-japan-rollout.md#c7sqlite-路由系統性跨縣市修正) 更新：精確搜尋達限可使用有界道路估算，總預算 22 秒；下列原始 2 秒量測保留作歷史比較，不代表目前跨縣市能力。

日本全國的建置／實測／限制另見 [日本全國整合紀錄](osm-japan-rollout.md)；以下台灣數字不作為日本效能保證。

驗證日期：2026-10-25（Asia/Taipei）。本機相同台灣圖資，1,541,279 個道路節點、1,945,578 筆路段與 711,743 筆地點。數字是單次可重現量測，會受磁碟與同機工作負載影響。

## 原因與修正

1. 原 `CompactRouter` 只保留一個交通方式的完整 Python 圖。切換模式會重新掃描全台道路、配置圖物件，需約 6.7–9.3 秒。現在道路留在 SQLite，按節點讀取、使用有限大小的鄰接與座標快取，各模式能共存，不需重建全圖。
2. 原搜尋只設迭代／時間上限，無法先辨識不連通路網；失敗也不快取。現在預先建立每個模式的弱連通分量，確定不連通時直接回報；同分量內仍遵守單行道，使用雙向 A*。弱連通只排除不可能的路線，不代表一定可按該方向通行。
3. 原台灣地點搜尋將 263 MiB JSON 與整理後的所有搜尋物件放在 HTTP 程序，實測服務約 1.9 GiB。地點與路由初始化還共用鎖。現在台灣搜尋逐筆串流準備 SQLite 索引，查詢只解碼前 30 筆完整結果，兩者使用獨立初始化鎖。原有沖繩別名搜尋保留。

## 同組路由量測

命令：`python3 -B osm/scripts/benchmark-routing.py`。舊實作可用 `--module-dir <舊 routing.py 與 compact_routing.py 所在目錄>` 比較。表中初始化不含離線索引準備。

| 測試 | 修正前 | 修正後 |
| --- | ---: | ---: |
| 路由物件初始化 | 1.789 秒 | 0.001 秒 |
| 市區開車，首次模式 | 6.754 秒 | 約 0.04 秒 |
| 切換步行 | 9.333 秒 | 約 0.04 秒 |
| 已暖機的台北車站至 101 步行，約 5.6 公里 | 0.156 秒 | 約 0.25 秒 |
| 不連通跨島步行 | 1.589 秒 | 約 0.007 秒 |
| 重試相同失敗路段 | 1.603 秒 | 約 0.001 秒 |
| 切回開車，另一組座標 | 7.283 秒 | 約 0.03 秒 |
| 上述獨立路由程序記憶體峰值 | 821 MiB | 約 30 MiB |

已載入全圖的單一路段，按需讀取 SQLite 可能比原本常駐大圖慢；此改動主要消除模式切換、失敗重算及整份資料載入的延遲。上述成功案例的距離與時間與舊實作一致。

網頁實際使用的 `/local-map/datasets/taiwan/api/route` 另測：首次開車約 0.13 秒、切換步行約 0.047 秒；同時執行「台」地點搜尋（24,891 個符合結果，回傳前 30 筆）約 0.34 秒，路由不需等搜尋完成。該服務程序在此工作負載下約 32 MiB。這不是所有路段與搜尋的記憶體上限。

台中海洋館附近的重現路段仍回傳 438 公尺、351 秒，未再出現雙零。

## 準備、邊界與驗證

資料索引是可刪除的衍生物，不更動原始圖資：

```sh
python3 -B osm/scripts/prepare-routing-index.py osm/data/taiwan-routing.sqlite
python3 -B osm/scripts/prepare-search-index.py osm/data/taiwan-places.json
```

首次準備此份圖資約需 19 秒（路網）及 33 秒（地點），之後重用；來源檔案或索引版本改變會重建。`osm:setup` 與服務啟動流程已包含準備；啟動使用短命子程序準備索引，在接受 HTTP 請求前釋放準備工作的記憶體。資料更新後需重啟服務。衍生檔位於 `osm/data/.routing-cache/`、`.search-cache/`，不提交至 Git。

搜尋失敗短期快取 30 秒，最多 128 筆。每個模式的正向與反向鄰接各快取 4,096 個節點，共用座標／分量快取 32,768 筆。路由的正常／擴大接點重試共用約 2 秒搜尋預算，另有限制展開節點與搜尋狀態數。超長跨縣市路段仍可能達到上限，會明確要求分段，不會將超時宣稱為道路不連通。

`npm run osm:test` 包含 60 組與獨立 Dijkstra 比較的有向圖／多接點測試、模式切換、連通分量、索引失效／原子準備、搜尋排名與串流邊界，以及搜尋與路由鎖獨立性驗證。
