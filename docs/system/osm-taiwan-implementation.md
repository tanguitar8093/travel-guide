# OSM 台灣／沖繩實作與驗收

## 使用方式

資料偏好設定保留 Google Maps／OpenStreetMap。選用 OSM 後，在「地圖」頁面選沖繩或台灣；目前地圖依瀏覽器保存。地圖為已提供圖資的固定地圖，不能任意編輯涵蓋範圍。

地點、標籤與一般行程清單依目前地圖顯示；新增行程預設使用目前地圖。既有資料不會因切換而刪除。公開行程可預覽其他 OSM 地圖，地圖依快照所屬地圖載入。行程地圖與路線依資料本身的地圖／座標選擇圖資。

OSM 地點必須具有座標，且在每一個所屬地圖的涵蓋範圍內。搜尋、手動座標、Google Maps 連結、儲存、備份、雲端寫入與共享編輯都檢查範圍。OSM 行程不接受其他地圖的地點。快速匯入 API 由座標判定歸屬台灣或沖繩，沿用既有 RPC 簽名。

## 圖資與架構

- `shared/geo/osm-datasets.json`：前端與 Python 共用的 dataset 名稱、中心、視野及 coverage。台灣 coverage 取自本次 Geofabrik 資料內完整島嶼海岸，簡化後加入 0.005 度沿岸容差，避免港口／岸邊地點被誤擋；不是把整個外框矩形都當成可加入範圍。
- `Region.osmDataset`／`regions.osm_dataset`：明確的資料歸屬；缺少欄位的既有 OSM 地圖仍代表沖繩。原沖繩 UUID 與帳號雜湊規則保持相容，台灣採自己的穩定 UUID。
- `/datasets/taiwan/tiles.json`、`/datasets/taiwan/api/search`、`/datasets/taiwan/api/route`：同一服務提供不同圖資。既有無 dataset 前綴路徑仍代表沖繩。
- 圖磚、搜尋與路網分開載入，載入台灣 catalog 不會阻擋底圖。SDK 與地圖操作共用 MapLibre adapter。
- 台灣路網預處理為 SQLite：交叉點及必要的中間點進入圖，完整彎曲道路幾何留在磁碟，回傳路線時再讀取。小型離島道路不再因連通區太小被排除。
- 雲端有兩份增量 migration：dataset 格式／驗證與固定地圖匯入相容修正。同步、共享、公開行程及備份還原都保留 dataset。
- 同步只允許內容完全符合預設值的 `regions.prepareOsm` 操作在跨裝置時合流；一般同 ID 建立或內容不同仍保留真實衝突。先前被誤分類的相同預設地圖可重試，未移除使用者資料或未確認的上傳 payload。
- 步行試算在最近道路候選全部不連通時，會擴大附近候選重試，仍遵守原本的吸附距離限制；避免車站內孤立樓梯使正常市區步行路線失敗。
- 手動同步與自動同步使用相同狀態發布流程，成功重試會清除舊的黃色錯誤訊息。

## 資料產製

```sh
sudo apt-get install python3-venv tippecanoe
npm run osm:setup -- --dataset taiwan
# 使用已有 PBF：
npm run osm:setup -- --dataset taiwan --pbf osm/data/taiwan.osm.pbf
npm run osm:build:tiles -- --dataset taiwan
npm run osm:test
```

下載來源為 https://download.geofabrik.de/asia/taiwan.html 。下載流程檢查上游 MD5，建置用 Python 套件固定版本。輸出 `taiwan.mbtiles`、`taiwan-places.json`、`taiwan-routing.sqlite`、中間檔與 `taiwan-manifest.json`。manifest 記錄版本、數量及 SHA-256。大型台灣產物不納入 Git，部署另一台主機時需要建置或複製。

一般資料更新不自動改 coverage，以免更新資料時改變既有儲存驗證規則。刻意更新 coverage 時，先產製底圖，使用 `osm/.venv/bin/python scripts/update-osm-coverage.py`，審查差異並以新 migration 更新資料庫中的同一份範圍；須重跑前後端範圍驗證。

更新圖資完成後重啟服務，避免同一服務混用不同批次的 cache。Docker 已包含共用 dataset 配置。

## 驗收順序

1. 偏好選 OSM，到地圖頁切換台灣；確認新增地點、行程與全景使用台灣。
2. 搜尋台北 101／鼎泰豐，加入地點，重整後確認資料存在。改輸入沖繩座標，應顯示範圍錯誤。
3. 切沖繩確認台灣地點不混入，沖繩地點與行程仍保留；再切回台灣確認資料。
4. 建立台灣行程，加入同區地點，檢查底圖、標記、路線與距離／時間；試算島內與跨縣市道路。
5. 混合模式儲存後同步，用另一個瀏覽器登入檢查。重複建立固定預設地圖不應出現假衝突；真正不同的編輯仍須顯示衝突。
6. 離線儲存後重連，手動同步失敗後成功重試，確認待同步筆數及錯誤訊息恢復。
7. 公開行程預覽／套用、共享編輯及備份還原後確認 dataset 與地圖限制仍正確。

## 已知限制與後續選擇

- OSM 具名資料不是完整商家名錄，名稱、營業時間、地址與電話的完整度依 OSM 而定。
- 台灣涵蓋本島及本批資料內的離島；已驗證澎湖、金門、馬祖、綠島、蘭嶼。東沙／太平島等不在目前圖資範圍，海上跨島路線沒有輪渡連接就無法計算。
- 沿用沖繩的汽車／步行／單車靜態路線估算，沒有即時交通、大眾運輸、機車 profile 或完整轉向限制。底圖沿用相同簡化圖層，不是商業地圖的完整標籤與店家樣式。
- 台灣搜尋與路網第一次使用會冷載入；目前主機可用，但較小主機需要記憶體評估。若要提高重啟後第一次搜尋速度，可另做磁碟搜尋索引。
- 不自動決定使用者真正有差異的同步衝突；不以清空快取／資料庫或丟棄待同步操作解決問題。
- 後續可決定圖資更新頻率、是否增加其他離島，以及是否投入更快的路線／搜尋引擎；都不影響目前兩地圖的操作方式。
