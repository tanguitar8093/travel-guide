## 方案與範圍

採用已確認的方案：**發佈時完整 clone，一個來源行程只保留一筆公開版本；更新直接覆蓋，下架直接移除公開快照。**

| 方案 | 資料獨立性 | 資料量與複雜度 | 評估 |
|---|---|---|---|
| 發佈時 clone | 原資料修改、刪除不影響公開內容 | 多保存一份資料；公開內容邊界清楚 | 採用 |
| 套用前讀原資料 | 公開內容依賴原行程、地圖與地點 | 可省快照，但需要處理原資料變動及公開欄位的讀取權限 | 不採用 |

本次只處理公開行程核心功能，使用獨立 POC IndexedDB；多人共同編輯、雲端同步與 Supabase 設計不在本次實作範圍。

- **下架確認視窗**：說明「下架後不再出現在公開列表，無法預覽或套用；已套用的個人副本保留」；提供取消與確認下架。
- **公開列表**：保留既有欄位，在新增日期下方補充有更新時的「更新日期」。更新保留公開記錄 ID 與新增日期；下架後移除該列。
- **再次發佈**：下架後恢復「發佈」按鈕；重新發佈建立新的公開 ID 與新增日期。
- 保留原有搜尋、篩選、唯讀覆蓋層與套用後自行選取副本的流程；設計稿仍使用記憶體示意，重新整理重置。

同步更新 [UI 說明文件](../../poc/ui/README.md)：記錄新增流程為待確認修訂，保留先前核准日期，修正 POC 準則連結。

## 資料與操作契約

- 公開記錄保存 `id`、`sourceTripId`、`createdAt`、`updatedAt` 與獨立快照。`sourceTripId` 僅用來識別更新對象，不用來讀取原資料；索引限制同一來源只有一筆公開記錄。
- 快照完整保存行程、所屬地圖、行程引用的地點及所有行程項目。重建這些資料的 ID 與內部引用；同一地點被多次引用時只複製一次。
- 保留日期、排序、抵達時間、停留時間、交通方式、既有路程資訊及行程項目 `note`；排除私人標籤、地點 `notes` 與未使用的地點。
- 更新時確認 `sourceTripId` 與目前個人行程 ID 一致，重新產生完整快照並原子覆蓋；不做內容比對、不保留歷史版本、不自動更新。
- 套用時從公開快照再次 clone，建立個人的地圖、地點、行程與項目，重新產生 ID 與引用。即使個人已有相同地點或地圖，也不合併。
- 下架刪除公開記錄，不修改來源或已套用副本；原行程刪除也不連帶刪除公開快照。
- 下架後無法再從公開列表預覽或套用；再次發佈視為新增公開記錄。
- 核心介面提供列表、讀取快照、依來源查詢、發佈、更新、下架與套用；更新對象不存在或來源 ID 不符時拒絕操作，不自動改成新增。

## 測項與交付順序

新增 UI workflow 確認後，依 [POC 流程準則](../../.agents/skills/poc.md) 進行 TDD：

- **發佈與更新**：資料完整、私人欄位排除、來源唯一、ID 比對、整份覆蓋、取消無變更；修改或刪除來源不影響快照。
- **套用與獨立性**：地圖、地點、行程與項目全部複製，引用正確；重複套用互不影響，更新或下架不影響既有副本。
- **下架與重發**：下架後列表、預覽與套用均不可取得；重新發佈產生新公開記錄。
- **IndexedDB**：重新開啟資料仍存在、範例初始化不重複、寫入失敗完整回滾，不顯示成功。
- **UI 驗收**：發佈／更新／下架按鈕狀態、確認與取消、通知、日期顯示，以及原有搜尋、預覽與套用流程。

交付順序：

1. 修訂 UI 設計稿，由使用者確認新增 workflow。
2. 使用 Vitest 先寫測項，建立行為契約。
3. 定義獨立 POC IndexedDB 資料核心、範例資料，以及欄位／範例 key-value Markdown。
4. 依測項實作商業邏輯與 POC UI；IndexedDB 階段的資料在重新整理後仍須保留。
5. AI 驗證針對性測項後，交付使用者手動 E2E。
6. 使用者手動確認後，AI 才編寫 E2E 程式；AI 不執行，由使用者觀看並執行實際操作。
7. E2E 通過後，POC 完成；下一階段另行評估 Supabase 設計。

## 已確認的預設

- 不保留公開版本歷史或下架歷史。
- 日期沿用來源行程，套用不自動改期。
- 每次套用建立不同副本；沿用設計稿的「（副本）」「（副本 2）」命名示意。
- POC 以本機示意資料呈現公開瀏覽；未來跨帳號使用時，來源 ID 比對之外仍須另行設計發佈者權限。
- 各階段完成狀態以本文交付紀錄為準；測試契約與資料庫定義完成不代表商業邏輯或 UI 串接完成。

## 分享副本管理修訂

使用者要求套用時能辨識並統一管理複製資料：套用地圖命名為 `<公開地圖名稱>(分享)`；每次套用新增獨立標籤 `<公開行程名稱>(分享)`，隨機選色，所有複製地點使用該標籤。標籤加入套用交易，建立標籤或後續寫入失敗均完整回滾。公開快照排除來源私人標籤的規則維持不變。

POC 側欄提供地圖、地點與標籤列表；地點可依地圖／標籤篩選，標籤列表顯示所屬副本行程。27 項測試涵蓋套用命名、每份副本獨立標籤與失敗回滾。舊副本不自動改名或補標籤，請以新套用副本驗收。

## 跨帳號公開可見性修正

公開快照改存瀏覽器共用 `travel-planner-public-catalog`，不同登入帳號讀取同一公開列表；套用副本留在接收者自己的工作區。保存發佈者與來源工作區，核心與 UI 均限制只有發佈者可更新／下架。舊帳號資料庫的公開記錄一次性匯入，marker 防止下架後重新出現。跨帳號測試覆蓋可見性、預覽、套用隔離、權限、更新／下架、遷移與回滾。共用範圍為同一瀏覽器與 origin；跨裝置的公開服務仍待後端階段。
