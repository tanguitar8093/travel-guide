## 保留的畫面與流程

1. 公開行程：行程名稱、區域、新增日期、預覽、使用行程，支援搜尋與區域篩選。
2. 唯讀預覽：在原頁上方顯示覆蓋層，可切換日期；網址不變，無編輯操作與私人標籤。
3. 使用行程：顯示套用成功；由「我的行程」或左側「行程」進入後，可在選單選取新增副本。
4. 我的行程：切換行程與日期，示意修改名稱、抵達時間及行程備註。依現有專案樣式，以「行程操作」下拉選單收納「編輯行程」及公開管理操作；行程頁不另設「公開行程」連結按鈕，透過側欄進入公開列表。
5. 發佈：顯示確認視窗，完整複製當下的區域、行程使用的地點與每日安排，重建 ID 與引用關係，排除私人標籤及地點備註，保留行程項目備註；後續修改原行程不會更動已發佈版本。同一來源行程只有一筆公開版本。
6. 更新公開版本：「行程操作」選單中，未發佈時顯示「發佈」，已發佈時改為「更新」並提供「下架」。確認更新後，使用目前內容完整覆蓋公開快照，不做內容比對；保留公開 ID 與新增日期，在公開列表補充更新日期，已套用副本不受影響。
7. 下架：確認後移除公開快照，不再提供預覽或套用；保留原行程與已套用的個人副本。下架後按鈕恢復「發佈」，再次發佈建立新的公開記錄。

## 建議檢視順序

1. 開啟公開列表，先套用京都三日行程；進入「我的行程」，從選單選取副本確認內容。
2. 切回原始京都行程（初始已發佈），修改名稱、第一個地點的抵達時間與行程備註；回公開列表預覽，確認公開內容仍是修改前的版本。
3. 回到原始行程，從「行程操作」選取「更新」，先取消確認內容未變，再確認更新；公開列表名稱、預覽內容與更新日期應改變，已套用副本保持原內容。
4. 回到原始行程，從「行程操作」選取「下架」，先取消確認公開記錄仍在，再確認下架；京都公開記錄消失，原始行程與副本仍可選取與編輯。
5. 在原始行程再次發佈，確認公開列表重新出現目前內容。也可選取尚未發佈的副本，確認它有獨立的「發佈」操作。

這份 HTML 是核准畫面的獨立保存稿，使用原 UI 的樣式與範例資料，互動以內嵌 JavaScript 示意。地圖為路線示意，所有變更只保留在本次開啟期間，重新整理即重置。側欄其餘模組僅保留視覺位置。

目前停在更新／下架設計稿待確認階段，尚未進入測項、IndexedDB 或後端實作。本次只涵蓋公開行程；多人共同編輯與雲端同步不在範圍內。
